나중에 가장 힘들 것 같다고 생각했는데, 한 번만 쓰는 파일은 거의 쌓이지 않았습니다. 대신 공통으로 올릴지를 작업자가 그때그때 판단해야 했습니다. 이건 협업에서도 작업하다가 고민을 한 부분입니다.

 그래서 
디자인 시스템을 설계할 때는 먼저 여러 화면에서 반복되는 UI 패턴과 공통 요구사항을 분석했습니다.
이후 색상, 타이포그래피, 간격 등의 디자인 토큰을 정의하고, 버튼이나 입력창, 모달처럼 반복적으로 사용하는 UI를 공통 컴포넌트로 분리했습니다.
컴포넌트는 특정 도메인에 종속되지 않도록 설계하고, 상태나 동작의 차이는 Props로 제어할 수 있도록 구성했습니다.
