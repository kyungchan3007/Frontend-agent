# 앱 안 vs 패키지: 개발자 입장 비교 (2026-11-03)

> 같은 앱(화면 3개, 공통 컴포넌트, 공통 모듈)을 두 구조로 놓고 직접 비교했다. 채점과 비용은 넣지 않았다.

| 구조 | 공통 코드 위치 | 가져오는 방법 |
|---|---|---|
| 앱 안 | `src/ui` · `src/shared` | `./ui/index.js` |
| 패키지 | `packages/ui` · `packages/shared` | `@app/ui` |

## 매일 쓸 때

| 항목 | 앱 안 | 패키지 |
|---|---:|---:|
| 설치 | 2.0초 | 1.9초 |
| 빌드 | 0.65초 | 0.65초 |
| 개발 서버 시작 | 0.33초 | 0.32초 |
| 버튼 수정 반영 | 0.16초 | 0.16초 |
| 새로고침 없이 반영 | O | O |

- 설치는 내려받은 캐시를 쓴 시간이다

## 패키지로 옮길 때 할 일

- 공통 코드와 문서를 패키지 폴더로 옮긴다
- 화면의 가져오는 경로를 패키지 이름으로 고친다
- 패키지마다 설정을 새로 만든다
- 루트 package.json에 workspaces를 등록한다
- `npm install`로 연결한다

- 화면이 없을 때 에이전트에게 맡기면 31초 걸렸고, 빌드도 통과했다
- 화면이 있을 때 옮기는 시간은 비교하지 않았다. 화면이 늘수록 고칠 경로도 는다

## 실수했을 때

| 상황 | 증상 |
|---|---|
| 패키지 연결이 빠짐 | 빌드가 실패해서 바로 알 수 있다 |
| Tailwind `@source`를 뺌 | 이 구조에서는 문제없다. 스타일이 그대로 나온다 |

- 에이전트는 `@source`를 넣었지만, 패키지가 같은 프로젝트 안에 있으면 없어도 동작했다

## 읽는 법
- **속도는 차이가 없다**: 설치 · 빌드 · 수정 반영이 같았다
- **옮기는 일은 단순하다**: 대부분 파일 이동과 경로 수정이다
- **앱 하나에서는 얻는 것도 안 보인다**: 코드는 같고 설정 파일만 늘었다
- **패키지가 완전히 독립하지는 않았다**: 토큰이 앱의 `src/tokens.css`에 남아, `@app/ui`만 떼어 쓸 수 없다

## 그래서
- 앱이 하나면 `src/ui` · `src/shared`로 시작한다
- 다른 앱과 함께 쓸 일이 생기면 그때 패키지로 옮긴다
- 패키지로 옮길 때는 토큰도 함께 옮긴다

## 한계
- 작은 앱 하나로 한 번 비교한 값이다. 큰 앱에서는 빌드와 반영 시간이 다를 수 있다
- 패키지의 장점인 여러 앱 공유, 경계 강제, 버전 관리는 비교하지 않았다
- JavaScript로 비교했다. TypeScript는 경로 · 타입 설정이 더 필요할 수 있다
- 사람이 직접 옮기는 시간은 포함하지 않았다
