# 실험 설계

> 실행 전에 고정한다. 소형 과제의 채점 규칙은 확인 뒤 `rules-small.md`로 따로 둔다.

## 질문
- 같은 시안과 문서를 줄 때, 무엇을 더해야 프론트엔드 결과가 좋아지는가?

## 고정값
- 규모별 문서 구성은 비교하지 않는다
- 모델: Sonnet 5.5
- 실행 환경: React + Vite + Tailwind, 390×844
- 시안: 내려받은 사본만 사용. 실행 중 Figma에 접근하지 않음
- 서버: 고정 응답을 주는 가짜 API
- 작업 폴더: 저장소 밖 빈 임시 폴더

## 규모별 과제

| 규모 | 문서 | 구현 범위 |
|---|---|---|
| 소형 | SDD · 엔티티 | 과목 선택 시트 + 상태 4장 |
| 중형 | 온톨로지 · SDD · 엔티티 | 공부 측정 흐름 |
| 대형 | 온톨로지 · PRD · SDD · 엔티티 | 측정 + 그룹 + 선생님 |

## 비교 조건

| 조건 | 시안 전달 | 자동 게이트 | 브라우저 확인 |
|---|---:|---:|---:|
| A | 이미지만 | X | X |
| B | 이미지 + 설명 패널 + 지도 | X | X |
| C | B와 같음 | O | X |
| D | B와 같음 | O | O |

- C가 하네스 기본 구성이다
- 과제 3개 × 조건 4개 × 3회 = 36회

## 채점

| 항목 | 방법 |
|---|---|
| 동작 | 숨은 Playwright 테스트 |
| 화면 | 시안 이미지와 픽셀 비교 |
| 규칙 | 토큰 밖 값 · 터치 44 · 접근성 검사 |
| 안정성 | 3회 모두 통과한 항목 비율 |
| 비용 | 비용 · 시간 · 턴 · 문서 읽은 횟수 |

- 정하지 않은 항목은 채점하지 않는다
- 픽셀 비교 기준값은 기준 구현으로 잰 뒤 실행 전에 고정한다
