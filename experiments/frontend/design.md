# 실험 설계

> 실행 전에 고정한다. 소형 과제의 채점 규칙은 확인 뒤 `rules-small.md`로 따로 둔다.

## 질문
- 같은 시안과 문서를 줄 때, 무엇을 더해야 프론트엔드 결과가 좋아지는가?

## 고정값
- 문서 구성은 SDD · 엔티티로 고정하고 비교하지 않는다
- 모델: Sonnet 5.5, effort low
- 실행 환경: React + Vite + Tailwind, 390×844
- 시안: 내려받은 사본만 사용. 실행 중 Figma에 접근하지 않음
- 서버: 고정 응답을 주는 가짜 API
- 작업 폴더: 저장소 밖 빈 임시 폴더

## 과제
- 범위: 작은 프로젝트만 (2026-11-03 사용자 결정)
- 구현: 과목 선택 시트 + 상태 4장

## 비교 조건

| 조건 | 시안 전달 | 자동 게이트 | 브라우저 확인 |
|---|---:|---:|---:|
| A | 이미지만 | X | X |
| B | 이미지 + 설명 패널 + 지도 | X | X |
| C | B와 같음 | O | X |
| D | B와 같음 | O | O |

- C가 하네스 기본 구성이다
- 조건 4개 × 3회 = 12회

## 채점

| 항목 | 방법 |
|---|---|
| 동작 | 숨은 Playwright 테스트 |
| 화면 | 시안 이미지와 픽셀 비교 |
| 규칙 | 토큰 밖 값 · 터치 44 · 접근성 검사 |
| 안정성 | 3회 모두 통과한 항목 비율 |
| 비용 | 비용 · 시간 · 턴 · 문서 읽은 횟수 |

- 정하지 않은 항목은 채점하지 않는다
- 픽셀 차이는 합격선 없이 연속값으로 비교한다

## 한계
- 실제 앱은 Expo이므로 네이티브 고유 문제는 비교하지 못한다
- 픽셀 비교는 사용감을 판단하지 못한다
- 더 큰 프로젝트는 비교하지 않는다
